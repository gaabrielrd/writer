# Preparar pull request

## Finalidade

Preparar uma descrição clara e completa da alteração para revisão.

## Quando usar

- Após concluir e revisar a alteração.
- Antes de abrir o pull request.

## Processo

1. Descreva o contexto e o objetivo da mudança.
2. Resuma as alterações realizadas.
3. Explique como testar.
4. Reúna evidências (saída de testes, capturas, logs).
5. Registre limitações e riscos.
6. Confirme cada item do checklist.

## Resultado esperado

- Contexto.
- Objetivo.
- Alterações.
- Como testar.
- Evidências.
- Limitações.
- Riscos.
- Checklist:
  - [ ] Critérios de aceite atendidos.
  - [ ] Testes.
  - [ ] Lint.
  - [ ] Typecheck.
  - [ ] Build.
  - [ ] Documentação.
  - [ ] Sem segredos.
  - [ ] Diff revisado.
